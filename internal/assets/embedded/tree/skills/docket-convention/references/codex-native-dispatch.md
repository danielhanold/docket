# Codex native dispatch

Use the top-level native named-agent control for every registered Docket role. Treat launch and worktree markers as role metadata. Retain the returned child identity and observe that same child until terminal return; a notification or success sentence is not a gate verdict. Forward the immutable assignment and dispatch context unchanged, while retaining parent capabilities and the outer gate key in controller-private storage.

Resolve the candidate Docket executable, its capability catalog, and `schema --operation agent.check-inputs` before work. Construct the schema-described assignment only after controller-owned preparation returns the root witness; prepare any child scope next, then construct and dispatch the separate private payload envelope. Each child verifies the same absolute executable commit independently. If the registered role, native dispatch control, required model, or catalog operation is unavailable, stop with a configuration diagnostic. Do not route through `agent.enter`, a shell runner, another harness, or a generic agent.

Bind catalog argv[0] to the verified absolute candidate executable, not bare `docket`. After incorporating the root witness, freeze/hash the final assignment and rerun `agent.check-inputs` at `prepare`. Copy its successful `entry_argv` unchanged into the payload: pinned executable and `--json`, no `--repo-dir` or payload flags. Those flags belong only to the outer invocation. Validate the final payload at `dispatch` before native dispatch; never reuse an earlier assignment's command.

On preparation, dispatch-validation or child failure, the controller records the concrete failure through catalog/schema-resolved `change.halt` with fresh version and verifies the durable halt before returning. Report halt-write refusals honestly. The parent obeys its keyed verdict; a halt does not confirm cancellation. Preserve the original epoch/native identity for explicit cancellation and supported resume.
