This is the actual docket-build scope inside the same native ImplementNext coordinator. Follow the real build skill and worker charter; these Codex fixture instructions supply the handoff detail. No separate build controller or replacement worker is permitted.

1. Verify the newly authored plan through normal Git/receipt/backlink/trailer checks and attach it. Resolve the configured suite using diagnostic.config from the feature root: effective.build.test_command.value must be go test -count=1 ./.... Verify current claim/workspace identity and clean feature HEAD. A known feature-only plan artifact-missing finding may remain; preserve it and independently verify the attached feature artifact. Do not copy the plan into primary or suppress other findings.
2. Run `python3 @@FIXTURE_ROOT@@/prepare-worker-inputs.py --feature <exact feature root> --plan-path <verified relative plan path> --routing-reason <actual standard-profile reason>` with explicit feature workdir and login=false. This helper serializes static data only, invokes no Docket operation, starts no agent or scope and writes no plan/code. It refuses reuse. It creates worker-inputs.json and dispatch-seed.json under the external fixture root. Preserve their hashes immediately. It reads only explicit feature/receipt paths. The assignment must be the actual fresh plan, never the earlier imported plan.
3. Before real scope creation, execute the seed's exact entry_argv from primary (login=false) as a controller input precheck. Require BINDING_OK. Do not rerun preparation mutation tests during the live run. Do not modify generated inputs after issuance. The native worker must independently execute the same argv as its own first shell call.
4. Prepare exactly one normal task scope. Load the JSON array from @@FIXTURE_ROOT@@/scope-identity-args.json verbatim; it was generated from the SAME hashed worker-inputs.json. Append that array to your OWN catalog-resolved gate.drive.prepare-scope argv, then append --gate-context with the unchanged outer context, --run-epoch with the exact returned epoch when supplied, and --json. Execute once with explicit feature workdir/login=false. Do not retype any identity field (the prior failure was scope task `1` versus worker task `task-1`). Capture complete stdout/stderr and process status privately before parsing; preserve the original grant. Do not recreate a scope on error.
5. Before native spawn, run `python3 @@FIXTURE_ROOT@@/check-worker-scope.py` with explicit feature workdir/login=false and JSON stdin `{ "scope": <complete actual prepare-scope response>, "gate_context": <unchanged actual token>, "run_epoch": <actual epoch or null> }`. Use proper shell quoting or a0600 private input file, not public evidence. This controller-only read-only checker loads the exact generated seed/input and the minted scope's pinned v3 identity. It checks task, change, phase, branch, worktree, repo, capability hashes, outer context, epoch and unused lifecycle. It invokes no Docket operation and launches nothing. A mismatch halts BEFORE dispatch, with no replacement scope or worker. The installed binary currently exposes no public scope-inspection operation; this fixture-only schema-pinned check is not a proposed production API.

   Capture the checker's complete JSON stdout without reconstruction into private functions.exec memory as verified_handoff. Require SCOPE_INPUT_OK. Set focused_scope=verified_handoff.scope, dispatch_seed=verified_handoff.seed, dispatch_gate_context=verified_handoff.gate_context, dispatch_run_epoch=verified_handoff.run_epoch. Never hand-transcribe the seed or its assignment. Keep the parent capability private. Save only status, task-input hash and noncredential identity in public evidence. Read and execute the entire @@FIXTURE_ROOT@@/dispatch-payload.js body in functions.exec. It emits DISPATCH_INPUT_OK and complete native dispatch_arguments only when all captured data match the verified handoff. No tool or agent is started by that data body.
6. Invoke native spawn_agent ONCE with those complete emitted dispatch_arguments unchanged. The target is docket-build-standard, fork_turns none. No independent wrapper, subprocess, root task or generic substitute. Retain the actual child identity and collect its terminal receipt.
7. On WAITING follow the real child handoff/controller claim/drain contract for the SAME drive. No new worker, scope or test start. On BLOCKED preserve state and settle ownership; no parent repair, commit or final suite. An exceptional takeover requires its documented event, not inference from a timer.
8. Only after COMPLETE, verify the task commit, clean worktree, real baseline/RED/GREEN, exact run roots and durable final acknowledgement. Confirm primary integrity. Continue the actual build-owned configured suite and safe results checkpoint under the launch instructions.

The worker receives dynamic child capability and outer gate context only in the private live operational message, separate from the credential-free immutable task JSON. It reloads that JSON inside every test shell call. Native message opacity must be reported honestly; successful scoped driver use can corroborate token delivery but does not prove all file-access behavior.
