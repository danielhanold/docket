## Findings

**Three consecutive clean task reviews, then two real defects at the whole-branch review.** Every per-task review returned no findings; the whole-branch review (dispatched on the most capable model, per the plan's own escalation) found one Important test defect and one Important false-prose defect. Both were invisible at task scope and only visible against the branch as a whole. Recorded because the pattern — a mechanical change whose per-task reviews all come back clean — is exactly when the final review earns its cost.

**1. A `sed` range END ADDRESS was a load-bearing coupling with no guard, and its failure mode was silent.** `tests/test_docket_example_yml.sh` isolates the commented `agents:` region with `sed -n '/^# agents:$/,/finalize-change:.*<cursor model literal>/p'`. The build correctly moved that anchor in lockstep with the value it keys on. The reviewer then asked the question the build had not: what happens if they ever *drift apart*? Mutation-tested: the slice grows from 33 lines to 63 — running to EOF and swallowing the `runners:` block and surrounding prose — and the test file still exits **green**, because every existing §(5) assert (exit 0, no unknown-harness warning, wrapper exists, status model) survives an over-wide slice.

The plan had written "The failure is loud but its cause is not." That was wrong in the direction that costs you: the failure was not loud at all. Fixed by pinning the slice's last line to the cursor `finalize-change` line, and mutation-verified in both directions (unmutated 182 ok / 0 red; mutated 181 ok / 1 red, the single red being exactly the new assert). This is the repo's own `verify-the-claim` lesson landing on a *risk* claim rather than a factual one — the class where over-caution is assumed to be free and nobody checks.

**2. Prose that names no literal is invisible to every grep sweep, and it was false.** `README.md`'s "Tuning agent models & effort" section said a `docket-implement-next` build runs at "the top tier, **at high effort**" and that an autonomous design pass "earns that same tier, **because deciding what to build is no cheaper than building it**." After the retune, `implement-next` is `claude-opus-5`/**medium** and `auto-groom` is `claude-opus-5`/**low** — so the first clause was false outright and the second asserted, as its justification, the exact opposite of what the new defaults do. The build edited `README.md:397` and `:425` and never revisited the paragraph 140 lines below.

Every literal-based verification on this branch was green throughout, and none of them could have caught this: the sentence names no model ID and no effort value. This is the third recorded instance of the same class in this repo (README asserting agent model tiers, factually false, all greps green). Fixed to describe the real relationship — same top-tier model, build at higher effort than design — and the neighbouring "mid tier" framing for `docket-adr` was tightened at the same time, since it read as a *model* claim that stopped being true when `adr` moved off `claude-sonnet-5` onto the build's own model at lower effort.

**3. Two sites the change body listed needed no edit; one it did not list did.** Reconcile established, and the build confirmed by measurement rather than assumption, that: the `.docket.example.yml` `codex:` block was already byte-equivalent to the target (no edit), and `tests/test_sync_agents_codex.sh` / `tests/test_sync_agents_cursor.sh` needed no edit because they pin only the **claude `status`** ID as the built-in a non-claude harness inherits — and `status` was the one agent already at its target value. Both files were verified green *and* verified untouched across the whole branch. Conversely, `README.md` and `sync-agents.sh`'s comment table carried the same stale literals and were **not** in the change body; they were folded in at reconcile.

**4. Guards were mutation-proven rather than assumed.** Wrapper effort drift, model drift, example-mirror-only drift, and the cursor `status` literal were each regressed on scratch copies and confirmed to redden the suite. No assertion was weakened anywhere on the branch — every changed assert moves a literal to its new value, and the reviewer verified the alias regex at `tests/test_sync_agents.sh:43` still matches `claude-opus-5`.

## Follow-ups

- **#0166 — retune the interactive skills' advisory session-model recommendation** (auto-captured during reconcile). `docket-new-change` and `docket-groom-next` get no generated wrapper, so each surfaces an *advisory* recommended model at startup; both still name `claude-sonnet-5`, pinned by string at `tests/test_sync_agents.sh:494-495`. After this change, every autonomous wrapper sits on `claude-opus-5` while the two interactive skills recommend a model no other docket surface names. Deliberately excluded here — what a human should run interactively is a different judgment than what a machine runs autonomously, and folding it in would have made a values-only retune also decide that question. The stub also asks whether the advisory should name a literal model at all, or point at the resolved tier so it cannot drift again.

- **The `docs/` exclusion in a stale-literal sweep is a trap worth not re-copying.** The plan's verification sweep originally excluded all of `docs/`, justified as "archived changes, plans, and specs — historical records." But `docs/` also holds live user-facing documentation (`docs/codex/`, `docs/cursor/`). No defect on this branch — those files were grepped directly and are clean — but the exclusion was narrowed in the plan text to the archive subtrees so the pattern is safe if reused. Not filed as a change; recorded here because the next person to write such a sweep will reach for the broad form.

- **Nothing in the repo validates a model ID against its harness.** Deliberate (ADR-0015 passthrough), and out of scope here. Worth a decision someday about whether the two unvalidated example blocks should carry a "last verified" date rather than a standing banner, since a stale example is indistinguishable from a fresh one.
