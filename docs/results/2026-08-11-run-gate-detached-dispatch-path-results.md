Two of these are worth remembering beyond this change.

**Finding 1 — the reviewer's own suggested fix was insufficient, and only the mutation proved it.**
The suggestion was to slice the detached section per branch and assert on each window. The fix
worker applied it and then ran the probe the finding demanded — merging the two bullets into one —
and the suite stayed **green**: `flat()` collapses the newline and the `- ` bullet marker into a
single space, so a pure bullet merge leaves both per-branch windows byte-identical to the unmutated
case. What closes the leg is a bullet-shape count taken from the **raw** template (`^- [*][*]`,
bracket expressions per the repo's awk rule), added on top of the slicers. A suggested fix is
plan-supplied procedure and gets the same scrutiny as plan-supplied code.

**Finding 4 — a deletion probe and an inversion probe are different probes.** The build's M2 probe
deleted the epoch conjunct and the guard reddened, which read as proof the conjunct was guarded. It
was not: the pattern pinned the token `DISPATCH_EPOCH` but not the direction of the comparison, so
flipping `>=` to `<=` left it green — and an inverted filter selects exactly the claims stamped
*before* the run started, which is a concurrent loop's claim being handed to a step that permits
re-dispatch. The fix added the operator as an ordered element of the pattern and probed it by
flipping, not by deleting.
