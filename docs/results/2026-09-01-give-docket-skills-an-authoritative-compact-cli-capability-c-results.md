## Findings

- **The catalog is built by walking the live Cobra tree, with effect + stable-op-id metadata co-located on each leaf registration via one `capability(id, effects...)` helper** — no second command-name→effect map. Producer mutation matrix (Task 5) executed: all five spec-required mutations (unclassified leaf, dropped entry, removed effect metadata, changed required flag, broken population floor) reddened their named guards and restored green.
- **Payload measurement (build evidence oracle):** the serialized catalog is **12233 bytes** at final HEAD, under the **12288-byte** design ceiling (55-byte margin). Fable-token estimate ≈ 12233/3.5 ≈ **3495 tokens** (heuristic chars-per-token; ESTIMATE, not a tokenizer measurement). The ceiling is a design event on breach, not a truncation opportunity — the margin is small, so the next added leaf/effect/flag hint will trip it and force a deliberate design decision. The HTML-escaping of `<`/`>` in signatures (~1830 bytes of `<`/`>` overhead) was **not** worked around by disabling the shared presenter's `json.Marshal` HTML escaping (a protocol-wide change out of scope); the budget was met with faithful backquoted value hints on flag usage strings instead.
- **ADR-0104 produced** — "The capability catalog is the authoritative executable CLI surface; workflow instructions resolve spellings from it, never hard-code CLI paths." This is the durable cross-cutting rule the change establishes and the repoguard shape guard enforces (`relates_to: [3, 20, 36]`).
- **Implementation decision (not ADR'd, recorded here):** the walker excludes Cobra's built-in `help` command via a docket-owned `capAnnotationExclude` machinery marker (added in `internal/cli/capability.go`) rather than hiding `help` — chosen to keep `--help` behavior unchanged and avoid risking a help-output golden elsewhere. Keyed on shape, available for any future machinery command needing the same treatment.
- **Guard scoping decision:** the repoguard shape guard (`internal/repoguard/capability_surface_test.go`) is scoped to **executable position** (a `docket <verb>` where the verb is a catalog family and a flag/subcommand follows, or a fenced/inline command span) so that product-name English prose ("docket metadata", "docket backlog") and bare command-group nouns are not flagged — resolving the tension that ~69 legitimate prose occurrences would otherwise match a naive `docket <word>` pattern, without hand-listing sites or laundering prose into the exemption set.
- **Review (docket-review-deep): 0 blocker, 1 important, 2 minor.**

Migrated all agent-executed/agent-prose sites to the `change.create` catalog idiom, removed the exemption entry, re-measured and re-pinned the remaining human-remedy exemptions (measured at HEAD, guard green = exact: `repository migrate`=9, `repository init`=3, `repository configure-tests`=3, `change create`=5 — the 5 remaining are genuine human-action prose, honestly pinned with a distinguishing comment). Zero agent-executed `docket change create` remain on guard surfaces.
  - *minor — DEFERRED (out of scope):* the repo-root `CLAUDE.md`/`AGENTS.md` "Run gate" and "Rebuild the binary" blocks still hard-code `docket run gate-before`/`gate-verdict` and `docket development install` argv, so the migration is not uniform with the Cursor mirror.
