## Findings

### Verified opencode behavior (scoped to version 1.18.11)

An observation about a harness is scoped to the version it was seen in, so the version travels with
each fact. Probed via `opencode debug agent <name>`, which prints the fully resolved agent config:

- opencode has **no first-class reasoning-effort field**. It forwards unrecognized agent-frontmatter
  keys to the provider as model options, so `reasoningEffort: <e>` arrives as `options.reasoningEffort`
  and is a real per-agent effort. This settled the spec's one open question.
- A double-prefixed OpenRouter ID (`openrouter/deepseek/deepseek-v4-flash-0731`) parses into
  `providerID: openrouter` + `modelID: deepseek/deepseek-v4-flash-0731`.
- `mode: subagent` is honored; the markdown body becomes the agent's `prompt`; the **filename is the
  agent identifier**, so no `name:` field is emitted.
- Both `.opencode/agents/` and `.opencode/agent/` are read. Plural was chosen because it matches
  docket's uniform `.<token>/agents/` plumbing and so needs no special-casing anywhere.
- **Two plumbing checks that saved work.** `.gitignore` needed no separate edit — the managed block
  generates its per-harness entries from `DOCKET_GI_HARNESS_TOKENS`, so registering the token covered
  it. And `link-skills.sh` needed no edit — opencode resolves skills from `~/.agents/skills/`, which
  that script already populates.

### Latent defect found and fixed

`ex_slice` in `tests/test_docket_example_yml.sh` builds a `sed` **address** from a model-derived
terminator. opencode's OpenRouter IDs are the first shipped values containing `/`, which closes the
address delimiter — `sed: invalid command code m` — and surfaces as an *empty slice*, so 33 mirror
asserts failed as though the block were missing rather than as a quoting bug. Fixed inside
`ex_slice`, which owns the address, so any future slash-bearing ID in any harness is covered.

### ADR

**ADR-0036** received a dated `## Update` rather than a new ADR. Change 0192 reverses and replaces
nothing: the two decisions (the project-root `AGENTS.md` dispatch block is COMMITTED; it is
MACHINE-NEUTRAL) both stand verbatim, and only their scope widens from Codex-only to any harness in
`AGENTS_MD_DISPATCH_HARNESSES`. The note records the rejected per-harness-block alternative (both
harnesses read the same single file, so per-harness blocks would collide), the accepted expressiveness
cost, and that removal is now keyed to the *last* dispatch harness being de-listed.

### Review findings — 0 blockers, 4 important, 4 minor

Reviewed at the **deep** rung. No blocker, so nothing was auto-fixed; these are left for merge-time
judgment. The four important ones, in the order a fixer should take them:

1. **`docs/codex/setup.md`'s de-list note is now false.** It still says de-listing Codex removes the
   `AGENTS.md` block; with the block shared, de-listing Codex from a repo that still targets opencode
   leaves it in place. `docs/opencode/setup.md` got the correct "last harness" caveat and the codex
   doc did not — the same hazard the change's own emitter comment names, applied to prose but not to
   this doc.
2. **No test exercises two dispatch harnesses at once.** The new coverage is opencode-only → `[claude]`;
   the codex test covers `[claude, codex]` → `[claude]`. Both pass against the *old* codex-only
   predicate, so the central property — a repo targeting both gets the block exactly once, and
   de-listing one while the other remains leaves it in place — is unasserted.
3. **The opencode emitter test asserts only frontmatter.** If body extraction or the skills preamble
   regressed to empty, the definition would carry no prompt at all and the suite would stay green.
   Both sibling emitters guard this (`codex TOML: dev_instructions carry body`, `cursor: wrapper body
   survives verbatim`).
4. **The effort-drop rationale is stated as verified behavior but was not probed.** The recorded probe
   covered only *model + reasoningEffort*; the model-less case was never run. Unlike Cursor — which
   must drop effort because it is encoded inside the model string — opencode has an independent key,
   so a model-less agent resolving against the configured default would plausibly still receive the
   option. The unverified claim currently ships in three places (emitter comment,
   `docs/opencode/setup.md`, the `.docket.example.yml` block comment).

The four minor findings: the shared block's new head claims defaults "on every harness it supports",
which overreaches past the shipped set to the unpinned `agents`/`kiro`/`windsurf` tokens; two new
guards in the opencode test key on enumerated spellings (vendor names, literal paths) rather than
shape, and grep the whole `AGENTS.md` rather than the marker-bounded block; the `--check` diagnostic
hand-lists "(codex, opencode)" instead of interpolating `$AGENTS_MD_DISPATCH_HARNESSES`; and the
agent-layer table's opencode cell holds a full path where the other three rows hold a bare extension.

### Plan deviations

Recorded because each is a plan defect a future planner should not repeat.

- **An unanchored `sed`.** The plan's normalize step ran `s/  */ /g` over every line of a fixture's
  `harness-defaults.sh` copy, which would have collapsed the two-space indent regexes inside
  `_hd_block` and silently broken the reader in that copy. Address-scoped to the assignment line.
- **Three plan-supplied asserts were replaced with stronger forms**, all because the plan's versions
  were vacuous or violated the repo's own rules: a file-wide `grep` that was green for every harness
  regardless of which block held the row (→ `hd_field` reads); a block-slicing `awk` regex (→ the
  sidecar's own reader); and an enumerated model-prefix list (→ shape dispatch, since `AGENTS.md`
  forbids enumerated spellings). Plan-supplied test code is unverified code, not an oracle.
- **The documentation update set was larger than the plan listed.** The mandated derivation grep found
  two further maintained surfaces in `README.md`, and `docs/codex/setup.md` carried *two* stale
  "thirteen-agent" counts rather than one. `tests/test_docket_build.sh` had to be edited outside its
  task's stated scope because two of its asserts quote a README paragraph the task was required to
  change — a restatement that had quietly become load-bearing.
- **The build gate went red once.** The added table row and widened prose pushed
  `agent-layer.md` past its enforced size budget (176/175 lines, 2009/2000 words). Repaired at the
  premium rung by a prose slim with the budget untouched; the cut restatements' normative sites all
  survive elsewhere, at the cost of one section hop for a reader following a deleted copy's path.
