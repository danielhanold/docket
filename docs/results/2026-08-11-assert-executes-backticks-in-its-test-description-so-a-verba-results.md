No automated test can close it — it is a scope decision, not a defect.
- [ ] **Confirm the suite-wide ban on legacy `` `cmd` `` substitution is wanted.** The checker flags a bare backtick in unquoted code position anywhere under `tests/`, which outlaws intentional backtick command substitution, not only the hazard. ## Findings

**A blocker that a green suite could not see, and that a documented mutation probe reported green.** The checker's line-continuation handler treated a backslash-newline as an *escape* rather than a *splice*, consuming the first character of the continuation line. Two consequences: with the house indent, the swallowed character was a space, which desynchronized the argument-index tracking so the `EVAL-BACKTICK` rule never fired — inert on **3707 of 6784** `assert` call sites, 55% of the suite; and at column 0 the swallowed character was the opening quote itself, inverting the lexer's quote state to end of file, silently discarding every later violation of every class. It was caught in whole-branch review, not by the suite, not by the fixtures, and not by the mutation probe the authoring worker ran and documented.

The root cause of *why it hid* is worth more than the bug: every red fixture wrote its hazard on one physical line, and the only fixture exercising backslash-continuation was a **green** one — which proves the machine does not false-positive across a continuation and says exactly nothing about whether it still detects. The general rule this yields: **a green fixture for a lexer state is not coverage of that state; pair every green fixture with a red one in the same state.** Fixed at `7eac5f65`, with `red/continuation_eval.sh` and `red/continuation_dq.sh` added. A three-mutant probe confirmed neither fixture is redundant — the original buggy clause reddens both, while each half of the defect reddens exactly one.

**A guard for a defect in the oracle cannot be validated by the oracle.** This change edits the assertion primitive all 108 test files depend on, so a defect makes asserts *pass*. Across seven build tasks and four fix tasks, the green suite established almost nothing; what actually found defects was fixture-level mutation probing, differential output capture, and direct execution of the hazard in a sandbox. The normalization sweep was accepted only after a fail-probe injected a deliberately false assertion into seven normalized files and confirmed each still printed `NOT OK` at column 1 and exited non-zero — because "the suite is still green" would have been satisfied by an assert primitive that could no longer fail at all.

**A `$(…)` desync found and fixed during the initial build (not shipped).** The spec'd state machine modeled `NORMAL`/`SQ`/`DQ` plus heredocs but not command substitution. On the live tree that was not a bounded over-report: `tests/test_sync_agents_runners.sh`'s `_between="$(awk -v q="'" '` read the inner opening quote as the outer's closing quote, ran the machine inverted for ~300 lines, invented 61 phantom heredoc hits and, in that window, could not see real ones. Command substitutions and parenthesized groups became nested contexts; suite hits fell 121 → 35, with every `NORMAL-BACKTICK` hit disappearing as a desync artifact. Same failure family as the blocker above — a lexer desync reports phantoms in one window and misses truth in another.

**The narrower rule was rejected on a probe, not on principle — ADR-0091.** The obvious optimization is to flag escaped backticks only in an assert's *condition* argument, since argument one is a description printed through `printf '%s'` and is inert. That is wrong: `cond="[ -n \"\`printf %s EXECUTED\`\" ]"; assert "d" "$cond"` prints `EXECUTED` and reports `ok`. The escape is consumed at the **assignment**, so `$cond` carries a bare backtick into `eval "$2"`. The assignment is a plain statement at word index 0, which an argument-position rule would never inspect — narrowing would have reopened a demonstrated execution path while leaving the suite green. Recorded as ADR-0091 so a future reader does not "optimize" it back.

**The original diagnosis was wrong and is now corrected in two places.** The stub and the learning file both attributed the 0212 incident to the helper interpolating its description into a double-quoted string, and proposed hardening the helper with `printf '%s'`. Parameter expansion does not re-trigger command substitution, so that fix alone would have prevented nothing and the incident would have recurred verbatim under it. The helper normalization still shipped — for ledger alignment, echo/escape hygiene, and to give rule (a) a byte-exact anchor — but it is explicitly not the safety mechanism. The learning `test-helper-interpolates-its-own-description` was rewritten on the `docket` branch (D4).

**A reviewer's safety argument was incomplete in the right direction.** Review proposed batching rule (a)'s per-file sweep into one awk process, arguing that per-file isolation was unnecessary because the sweep carries no cross-*line* state. True, but it carries cross-*file* globals — the `NR`-keyed line buffer, the report buffer, the dedupe key set, the report path — which an `FNR==1` reset alone would not have torn down. The batching landed with explicit `file_reset()`/`file_end()` teardown and was accepted only on a 270-invocation differential capture proving byte-identical output. Recorded because the near-miss shape is instructive: a correct-sounding safety argument that names the wrong invariant.

## Follow-ups

- **#0297** (minted this run) — relax change 0212's per-file `SITES` backtick ban now that the gate enforces the property repo-wide; move the block into a quoted-delimiter heredoc so backticked verbatim anchors become legal data again. Deliberately deferred: the relaxation is only safe *after* this gate merges.
- **`tests/test_run_tests.sh` budget row raised 20 → 30s**, from measurement, with the sweep batched first rather than the row raised to absorb the cost. Measured serially on a quiet machine: base `origin/main` 16.1s; this branch unbatched 27.2s; this branch batched 21.0s. Batching recovered 6.2s of the 11.1s the preflight added and made the residual cost O(1) awk processes per invocation instead of O(#test files). The row follows the table header's own rule (next multiple of 5, plus a 5s margin). `EXPECTED_TOTAL` in `tests/test_runtime_budgets.sh` moved 1740 → 1750.
- **Not absorbed, and not this branch's:** `tests/test_sync_agents_runners.sh` runs ~190s against a 60s ceiling (pre-existing, tracked as **#0280**); `tests/test_docket_status.sh` sits at the table's hard 60s ceiling (sharding tracked as **#0296**). Neither row was touched.
- **Known residuals in the checker, documented in its header rather than silently carried:** conditions assembled from variables at runtime are not modeled — the scanner reads source, not values; a backslash-escaped `\${#x}` in unquoted position still hands its `{` to the separator branch (that spelling means a literal dollar and does not occur in the tree); and a heredoc operator on a line that also ends in a backslash continuation activates the body one physical line early, which fails in the loud phantom-heredoc direction rather than as a silent miss and has no site in the tree.
- **Two dead `ok`/`nok` wrappers removed** from `tests/test_skip_allowlist_invisibility.sh` (the sweep made its `assert` print directly). The same-looking pair in `tests/test_frontmatter_read_shapes.sh` has 12 live call sites and was deliberately left alone.
- **Plan deviation worth knowing:** the plan's acceptance-test seed snippet was defective — its backtick executed a harmless `printf` while the marker write lived in the eval'd condition of an `assert` the seed never defined, so the marker could never appear and the whole zero-files-executed acceptance test would have been vacuously green. It was rewritten so the substitution itself performs the write, and the seed was run directly first to prove the marker really appears when executed. Plan-supplied probe code has now been defective in eight of this drain's changes (tracked as **#0292**).
- **Plan deviation, fail-closed:** the plan's wiring snippet guarded the gate with `[ -x "$HYGIENE" ] || [ -f "$HYGIENE" ]`, which silently skips the gate when the checker is missing (and whose `-x` is dead under an `||` with `-f`). A missing or unreadable checker now refuses the run with exit 2 — the "runner will not start" family — leaving exit 5 with the single meaning "the scan ran and found a violation".
- **Task order changed during the build:** Task 4 (normalization) ran before Task 3 (the regression test), because rule (a) sweeps `tests/` autonomously on every invocation, so the tree reported 106 `DEFN-DRIFT` violations until normalization landed — making Task 3's planned "green fixture → rc=0" assertion unsatisfiable in its original position.
