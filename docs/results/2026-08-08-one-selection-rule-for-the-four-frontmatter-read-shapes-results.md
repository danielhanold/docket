## Findings

**No ADR was produced, deliberately.** The spec's Assumption 1 rejects a third overlapping ADR by name: ADR-0057 (anchor when the key may be absent) and ADR-0058 (the two-tier logical/raw split) already record the *decisions*, and this change consolidates them into an operational selection table in the library header. ADR-0057 names change #0134 as its tracked follow-up; #0134 was killed into this change during the 2026-08-07 triage, so that pointer now resolves here. The ADR ledger is immutable and was not edited.

**Reconcile re-census (2026-08-08).** The spec's census had drifted. Roughly a third of the sites it listed were already migrated (`board-checks.sh`'s archive leg, `docket-status.sh:636/641`, `github-mirror.sh` type reads, `render-board.sh` type reads, all of `render-artifact-backlink.sh`), and one consumer absent from the census entirely — `scripts/verify-run.sh` — already read `status`/`pr`/`branch`/`claimed_at` through `fm_field`, landing on the correct side of the rule without ever having been told it. The variable-key read the spec expected to have disappeared (`field "$f" "$key"`) was still live at `board-checks.sh:442`, so Deliverable 5's "a variable-key call fails the guard by default" clause had a real subject rather than a hypothetical one.

**The build gate went red on the new test file's own content, twice over.** Two whole-repo shape guards fired on `tests/test_frontmatter_read_shapes.sh` — `test_grep_portability` on a literal `{0,600}` written *inside the comment explaining why bounded repetition is banned*, and `test_skip_allowlist_invisibility` on a fixture bait line. Both guards were right to fire: a guard that exempted comments could be evaded by relocating a pattern into one. The repair spelled the example bound in words rather than as a brace interval, which is the same self-membership discipline `test_grep_portability` already applies to itself (it assembles every >255 literal it needs at runtime). Worth remembering: `test_skip_allowlist_invisibility` scans **committed HEAD**, not the working tree, so its counts are stale until a commit lands.

**Review returned 8 findings (0 blocker, 4 important, 4 minor); all 8 were fixed in-branch** across 6 fix tasks. Three are worth carrying forward as lessons rather than as diffs:

- *The anti-vacuity floor was itself vacuous.* Fixture 1 asserted the renderer had run by grepping for `docket:artifacts:end` — but the fixture ships that marker in its own body, and with every optional read empty the rendered block is byte-identical to the pre-render one. The assert could not distinguish "rendered" from "never touched", and the render call discarded its exit status too, so a renderer crashing with exit 2 left all three asserts green. This was plan-supplied test code carried over verbatim: a plan hands you unverified code, not an oracle.
- *The rule's stated criterion contradicted its own classification.* The header defined "guaranteed present" as "the template ships it" — but the change-template ships `spec:`, `plan:`, `results:`, `branch:`, `pr:`, `blocked_by:` and `trivial:`, all of which the rule correctly anchors, and all seven are present in 266 of 266 change files today. Applying the header's own test would have promoted them back to `field()`, and the census guard's failure message actively invited exactly that. The criterion is now semantic optionality — *can any file this call site reads legitimately omit the key* — with template presence demoted to one sufficient reason a key is *not* guaranteed. Corpus presence today is a snapshot; the question is what a hand-edited file may legitimately do tomorrow.
- *The census allowlist flattened three corpora into one key-name union.* The header separates the guaranteed sets by corpus (change files, ADRs, learnings findings), but the guard matched on key name alone — so `field "$f" priority` in an ADR walker or `field "$f" title` in a learnings walker would have passed while reading a key its corpus does not carry, which is the precise failure this change exists to close. The fix keys the allowlist on (corpus class, key), fails closed on any call site whose corpus cannot be determined, and — the part worth keeping — **parses the guaranteed sets out of the library header's own sentence** rather than restating them. The guard can no longer drift from the rule it guards, because there is only one copy.

**Both `fm_field_verbatim` adoptions were unpinned by anything.** The whole stated reason `docket-status.sh` and `render-board.sh` read `blocked_by` verbatim is the ` #…` truncation (`PR #69 is stale` → `PR`), yet every existing fixture used a `#`-free value, so both sites passed identically under `fm_field` and a later "consistency" swap would have silently restored the defect. Fixed by giving each file a `#`-bearing fixture with a per-site mutation arm.

**Guards are code, and one-way by default.** Two smaller instances: a mutation counter in `tests/test_docket_status.sh` grepped `fm_field "$f" pr`, which is a literal prefix of the newly-added `fm_field "$f" promotion_state` — the count went 1→1 instead of 1→0 and the "mutation landed" assert failed; and the census fragment parser required exactly one space after the accessor, making a tab-separated call site invisible (fail-open, the dangerous direction) while a double-space one produced a spurious violation.

## Follow-ups

- **`scripts/render-learnings-index.md` carries a stale sentence** — "`field()` returns the raw scalar with surrounding quotes intact" — which has been wrong since change 0138: `field()` strips a matched pair and `field_raw()` is the one that preserves them. It sits in the paragraph immediately after one this branch rewrote. Left untouched deliberately: `hook` is not a read this change migrated, so correcting it here would have been scope creep. Not minted as a stub either — a one-line doc correction costs one edit, and routing it through a groom, a spec, a plan, a branch and a close-out would cost more than the defect.
- **The census's (script, file-argument) corpus map is hand-maintained.** Its failure mode is correct — an unknown call site is a violation, never a pass — but a hand-maintained list is an enumerated floor and ages toward the gap it was written to close. If a future change adds several new frontmatter walkers, deriving the corpus from the walker's directory literal rather than a map is the durable move.
- **`fm_field_raw` remains a documented orphan** with zero production callers, pinned at zero in both directions so that adoption and deletion are equally visible. That is the designed state, not neglect — it is the raw twin the next optional-key decoding consumer reaches for, and the raw/anchored quadrant of the rule table would otherwise be empty. Do not "clean it up".
- **Three prose asserts key on the rule table's exact column alignment** (whitespace-sensitive fixed strings). Reflowing that table will redden them. That coupling is intentional — it is what stops a phrase assert from being satisfied by a neighbouring paragraph that merely mentions an accessor name — but it is worth knowing before anyone tidies the table.
