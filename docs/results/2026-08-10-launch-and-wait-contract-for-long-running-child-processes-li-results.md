# Launch-and-wait contract for long-running child processes — results

Change: #0282 · Branch: feat/launch-and-wait-contract-for-long-running-child-processes-li · PR: (opened at close-out) · Plan: docs/superpowers/plans/2026-08-10-launch-and-wait-contract-for-long-running-child-processes.md · ADRs: 81

## Verify (human)

- [ ] **Accept or supersede the per-platform narrowing (ADR-0081).** On macOS `gate-run --launch` delivers own-process-group detachment plus the handshake, not a new session. Accepting a `perl` dependency (`/usr/bin/perl` is present; `POSIX::setsid` works) would close the gap and let the contract claim a new session everywhere — and `gate-execution-evidence.md`'s own four harness verdicts were measured with exactly that shape. Docket's recorded policy is that it takes no `perl` dependency. This is the one decision the build deliberately recorded and continued past rather than settling.
- [ ] **Decide whether the `129..192` residual is worth a non-shell helper.** A POSIX shell sees only `$?`, which cannot separate a genuine `exit 143` from death by signal 15, so the terminal record classifies that band as `kind=signal`. The bias is deliberate and argued in the contract, but the only real fix is the same non-shell dependency as the item above — they would be settled together or not at all.
- [ ] **Sanity-run the helper against a real suite once, by hand.** The suite exercises `gate-run` heavily through fixtures, and both this run's post-fix gates were themselves launched through it, but no test observes an agent following `docket-build`'s new posture prose end-to-end. `docket.sh gate-run --launch --root "${TMPDIR:-/tmp}" -- scripts/run-tests.sh`, then `--observe` until terminal, then `--stop` on a fresh one mid-flight.

## Findings

**ADR-0081 — the per-platform narrowing.** The session-primitive ladder was resolved by measurement at plan time, not deferred into a task. `setsid(1)` is absent on macOS; `script(1)` was probed against the full capability set and **rejected** on two independent grounds — it injects framing into the durable log (`/usr/bin/script -q /dev/null /bin/bash -c 'echo alive' </dev/null` yields the bytes `^D \b \b a l i v e \r \n`, a typescript marker plus pty CRLF) and a pty merges stdout with stderr, which the stdout-is-the-protocol rule forbids. It is also fragile with stdin on a socket (`tcgetattr/ioctl: Operation not supported on socket`). The ladder is exhausted without a new dependency, so the contract is narrowed honestly per platform and probes at runtime rather than by platform name. ADR-0080 is the direct precedent and measured the same technique for the delegation boundary.

**The wrapper carries `trap '' TERM`, and this was forced by measurement.** An untrapped wrapper dies alongside its own child on a group-directed TERM — the exact shape both the test fixtures and `--stop` step 4 use — which made `kind=signal` unreachable: every signal death degraded to no record at all. No *handler* is installed, so `wait` returning the command's own status remains the only path that writes the terminal record, and SIGKILL is still fatal to the wrapper, which is what produces `cause=vanished`. Folded into ADR-0081 as context rather than given its own ADR.

**The ordinary `--stop` on a live child reports `already-terminal`, not `stopped`.** The wrapper leads the recorded group, so step 5 cannot verify the group empty until the wrapper has exited — and the wrapper writes `terminal` before it exits. `stopped` is reachable only on the KILL-escalation path, where no record can exist. The plan's Task 5 fixture presumed the other leg and was unsatisfiable as literally written; every invariant it protected is still asserted, on the leg that can reach it. Callers are unaffected: `already-terminal` → re-observe → `state=stopped` → never relaunch.

**Two fixture defects found only by mutation testing, both of which would have shipped permanently-green asserts.** (1) The plan's pre-record canary `/bin/sh -c 'sleep 30 # gate-run-canary'` is a single simple command, so the shell **execs** it and the process's command line becomes a bare `sleep 30` — invisible to `pgrep -f`. The mutation passed under the plan's own fixture and only reddened after the fixture was fixed. (2) The plan's post-record wedge read the pgid via a glob over random `mktemp` names and would usually pick an earlier, already-dead run. Both are the repo's own *a guard is code* rule paying for itself.

**Twelve vacuous contract asserts, found by the whole-branch review and repaired.** An assert whose pattern is satisfied by text other than the thing it means to pin. The six-state loop was the worst: `running` matched the file's own title "long-running child", `failed` matched `launch-failed`, `passed` matched "a moment that has passed" — so **deleting the entire six-state table reddened none of the six**. All are now anchored on a sliced paragraph or a table row, each proven vacuous-before and load-bearing-after by deletion. Two more of the same class had already been caught mid-build.

**`--stop` step 3's pre-signal re-read initially reddened no assert**, and the honest reason turned out to be a real gap rather than an untestable invariant: step 3 emitted the same token and wrote the same nothing as step 4's absent-group branch *because it omitted step 1's orphan probe*. Adding the probe gave step 3 distinct, pinned behavior (`unavailable` vs `already-terminal`) and retired the residual instead of shipping it as an admission. The lesson generalizes: *"a residual is for what cannot be detected, not for what was not probed"* — the spec's own words, applied to the spec's own text.

**Platform traps hit three times, each a GNU tool on PATH masking a BSD bug.** BSD `wc -l` pads its output, so the plan's `[ "$(wc -l <<<"$obs")" = "1" ]` never holds; `date +%s%N` is a GNU extension whose absence breaks the *assert's own arithmetic* rather than the property under test; and `script(1)`'s BSD framing is what rejected that ladder rung. Same family as the repo's recorded "PATH grep is ugrep" finding.

**A pre-existing defect repaired incidentally:** `verify-run` (change 0237) was missing from `scripts/docket.sh`'s `# Usage:` block, exactly as `gate-run` was. The new facade sentinel asserts set-equality between the rendered `--help` op names and the dispatchable set, so shipping the guard without that line would have been red on arrival.

## Follow-ups

**Change 0284 — minted at reconcile.** `runner-dispatch --observe` is sentinel-only: no process-liveness probe at all, so a delegated agent whose process died without writing its sentinel reads as `running` for the whole `DELEGATION_OBSERVATION_BUDGET` (default **60 minutes**) before the bound fires. That is this change's own defect shape, in the dispatch lifecycle instead of the gate lifecycle, at ten times the worst-case latency. `runner-dispatch.sh` is a **conscious exclusion** here — its surface is agent-dispatch-specific and change 0277 is actively reworking it — and this residual is recorded in both the spec and this file so it does not depend on the mint having succeeded. Right sequencing: 0282 ships and proves the predicate, 0277 finishes its rework, then 0284 transplants it.

**Untaken suggestion, left open deliberately.** With no `--root`, `--launch` mints a `"${TMPDIR:-/tmp}/gate-run.XXXXXX"` *and* a `run.XXXXXX` inside it. The review floated dropping the redundant outer level; it was scoped out as a code change on a documentation finding. The contract now states that a run dir outlives its run on purpose (for post-mortem) and that disposal belongs to the caller or the OS temp reaper.

**Two named residuals a future change may close, both gated on the same dependency question as ADR-0081:** the `129..192` classification band, and — narrower — a child that escaped the recorded process group (double-fork, own session) surviving `--stop`. The helper signals the group it recorded and does not hunt descendants.

**`OVER BUDGET` on this repo's slow files is untouched and owned elsewhere.** Across five full-suite runs during this build the flagged set varied run to run — `test_docket_config`, `test_harness_defaults`, `test_harness_defaults_validator`, `test_sync_agents`, `test_sync_agents_runners` — which is itself evidence of how load-sensitive the wall-clock reading is, and is why the two new rows were **not** cut close to their measured values. Change 0280 owns the shards; suite speed is explicitly out of scope here. Neither new test file was ever flagged.

**Plan deviations worth knowing about at merge.** Task 5 landed **two** commits rather than one (`f3d4c215`, then `4ae059f3` correcting a stale-pgid read its own post-commit self-review found — appended, never amended). Task 7 touched `scripts/docket.md` and `tests/test_runtime_budgets.sh` beyond its stated file list because the facade and budget-total sentinels pin them. Task 8 raised two rows in `tests/test_skill_size_budgets.sh`, which had 4 lines of headroom before the change; the economy fix batch raised one again.
