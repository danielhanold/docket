# AGENTS.md — always-in-context rules for this repo

These rules must guide agent actions unprompted, including ad hoc commands outside tested code.
Promotion is a human decision. Keep detailed history in the learnings ledger on the `docket`
branch; the docket-convention skill's “Learnings ledger” section owns its mechanics.

## Shell

- Under `set -o pipefail`, never pipe a producer into an early-exiting consumer such as `grep -q`
  or `head`: SIGPIPE can produce exit 141. Capture first, then match with a here-string.
- Declare grep patterns beginning with `--`: use `grep -E -e "<pat>"` or
  `grep -qF -- "<pat>"`. Otherwise an option-parsing error can make a negated assert pass.
- In awk indent classes, use `[^[:space:]]`, never `[^ ]`, so tabs are included.
- Use `mv -f` on install/replace paths: BSD `mv` can refuse after a prompt yet exit 0.
  `git mv` is excepted because its `-f` permits overwriting a tracked target.
- Always template `mktemp`, with or without `-d`: `"${TMPDIR:-/tmp}/<name>.XXXXXX"`.
  Bare macOS `mktemp` ignores `TMPDIR`. For a same-filesystem atomic rename, create the
  temporary file beside its destination instead.

## Frontmatter and generated blocks

- Anchor a frontmatter-field edit to the first `---…---` block; body prose may contain
  column-zero `status:` or `updated:` lines.
- Quote YAML scalars containing colon-space, a trailing colon, ` #`, a leading indicator
  character, or a boolean keyword (`on/off/yes/no/true/false`). Scripts writing free-text
  frontmatter quote unconditionally at the write boundary (ADR-0071). This applies to
  scalars only: leave flow collections such as `depends_on: [3]` as collections.
- Before rewriting a managed block, validate marker order and balance. Refuse dangling,
  out-of-order, or nested markers and leave the file untouched.

## Guards and tests

- Mutation-test a guard: remove what it guards and observe failure. A mutation that stays
  green is a defect until explained.
- Key guards on syntactic shape, never an enumerated list of spellings.
- Derive a literal's or operation's sites from a whole-repository search, then distinguish
  prose from executable uses. Do not substitute a hand-listed set for that search.
- Run the whole suite at each build/finalize gate. Resolve `build.test_command` and
  `finalize.test_command` independently from config; run against the source checkout under
  review. This repo uses the Go runner in `internal/suiterunner`; no separate Bash oracle.
  See `tests/README.md` for suite execution and test placement.
- Budget reports need judgment even when the suite passes: `BUDGET WATCH:` and
  `PARALLEL-SENSITIVE:` are screening findings; `SERIAL CONFIRMED OVER BUDGET:` is an
  authoritative breach to act on. These reports do not fail the run by default.

## Comments and cross-references

- In maintained source, anchor cross-references on symbol names or verbatim-quoted clauses,
  never line numbers. `TestCommentAnchorStyle` in `internal/repoguard/anchors_test.go` covers
  only part of this rule; other forms still require authoring discipline and review.
- Preserve point-in-time pointers in results, archived changes, specs, and Accepted ADRs;
  rewriting them falsifies the record.

## Rebuild the binary after a merge to main

- After every successful PR merge into `main`, resolve `development.install` from the
  capability catalog and run it with `--source /Users/homer/dev/docket` so the installed
  binary matches source.
