# Put a groomed change on hold so loops skip it — Implementation Plan

> **For agentic workers:** this plan is executed by `docket-build`. It routes each task to the tier named in the task's **Tier** line, under the `docket-build-task` contract, and runs one full-suite gate at the end. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A change can carry `hold: true`. No autonomous build selection picks a held change, and a run that names that one change still builds it.

**Architecture:** The hold is a selection-only exclusion. `domain.EvaluateReadiness` gains a last step that turns would-be `build-ready` into a new kind, `on-hold`. `domain.SelectQueue` keeps only `build-ready`, so every selection path drops a held change, while `domain.ClaimEligibility` accepts `on-hold` as well as `build-ready`, so single-id paths still build it. `change.groom` and `change.create` set and lift the field, with an optional operation-owned `## Why on hold` section. The board keeps a held spec-backed change under Groomed with a new Readiness column. The skills learn the new word.

**Tech Stack:** Go (module `github.com/danielhanold/docket`), skill Markdown under `skills/` with embedded copies regenerated by `go generate ./internal/assets/`.

**Spec:** `docs/superpowers/specs/2026-10-18-mark-a-build-ready-change-as-off-limits-to-the-autonomous-lo-design.md` (metadata branch; also the first commit on the feature branch). Read it beside this plan.

## Global Constraints

- Field name `hold`. `hold: true` means held. Absent, valueless, or `false` means not held. A **malformed** value reads as **held**, and the existing `field-malformed` warning still fires.
- Readiness token: `on-hold` (`domain.ReadyOnHold`). `readiness_reason` for it: exactly `on hold`.
- Board cells, exact: Groomed Readiness is `build-ready` or `on hold`. A held trivial row in Proposed reads `on hold`. In progress column header is `State`, and its cells read `run halted — needs you` or `building`. No Groomed or In progress cell is blank.
- Request keys on both `change.groom` and `change.create`: `hold` (bool, three-state on groom: omitted keeps it, `true` sets it, `false` lifts it) and `hold_reason` (string, accepted only with `hold: true` in the same request).
- New finding codes (exact): `invalid-hold` (abstain carrying `hold`), `hold-reason-without-hold`, `invalid-hold_reason` (a reason that is whitespace-only, carries a column-zero `## ` heading outside fences, or leaves a fence open).
- Section heading, exact: `## Why on hold`. Do **not** add it to `render.ChangeOwnedHeadings`. Only the hold keys write it. A `sections` edit naming it is refused with `invalid-section-heading` on every groom outcome and on `change.reconcile`.
- Grooming and finalize are unaffected. Never change `docket-groom-next`/`docket-auto-groom` selection, and never refuse a claim because of a hold.
- Docs describe current behavior only: no change or PR citations (ADRs are OK).
- Agent-read skill prose is paid on every run, so keep each addition to one short sentence or clause. After any `skills/` edit, run `go generate ./internal/assets/` and adjust `internal/repoguard/budgets_test.go` rows with a `0560:` note.
- Comments in maintained source anchor on symbol names, never line numbers.
- Under Go, defeat the test cache for every mutation probe: `go test -count=1 …`.

## Review Focus

1. **A garbled hand edit** (`hold: yes`, `hold: [true]`, `hold: 'maybe'`) must read as held (`on-hold`, out of `ready`) with a warning, and must never error or open the change to the loop. Task 2 pins this.
2. **Held plus another blocker:** a held change with an unmet dependency or an unresolved stack base keeps that earlier readiness. A named run is still refused, and the board shows the waiting cell, not `on hold`. Tasks 1 and 4 pin this.
3. **Lifting a hold that has no reason section** (`hold: false` on a record without `## Why on hold`) must succeed. `render.ApplySectionEdits` errors on removing an absent section, so the remove edit is added only when the section is present. Task 5 pins this.
4. **A hand-duplicated `## Why on hold` heading**, when the request sets or lifts a hold, must refuse with `section-edit-failed` and write nothing. Task 5 pins this.
5. **Whitespace-only `hold_reason`** with `hold: true` is refused with `invalid-hold_reason` on both operations. It must never write an empty section. Tasks 5 and 6 pin this.
