# Link a change to a ticket Implementation Plan

> **For agentic workers:** This plan is executed by `docket-build` (task-by-task through its tier agents under the `docket-build-task` contract). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give a change three stored ticket fields written by one new operation (`change.link-ticket`) and by `change.create`, retire the dead `issue:` field, add the `tickets.*` config keys, and put a ticket line in implement-next's PR body.

**Architecture:** The domain owns one ticket model and one validation function (`domain.ValidateTicket`), shared by the decoder's read-side check, `change.create`, and the new operation. "Linked" means all three fields present and valid; anything else carrying a ticket field is "not linked" everywhere and raises one decode warning, `ticket-link-invalid`. The new operation is a request-file, revision-pinned metadata transaction built from the same pieces `change.block`/`change.relink` use (shape validation, `upsertFieldBytes`, `buildGroomCandidate`, `render.ArtifactBlockContent`, `includeBoard`).

**Tech Stack:** Go (`internal/domain`, `internal/repository`, `internal/render`, `internal/app`, `internal/cli`, `internal/config`, `internal/reposetup`, `internal/repoguard`), skill Markdown with embedded twins regenerated by `go generate ./internal/assets/`.

**Spec:** `docs/superpowers/specs/2026-11-09-link-a-change-to-a-ticket-design.md` (metadata branch). Read it with this plan; it holds the settled decisions and the config tool table copied into `.docket.example.yml`.

## Global Constraints

- Three flat scalar fields, exact names: `ticket_provider`, `ticket_id`, `ticket_url`. Stored as given, never derived.
- Validation (one function, every caller): `ticket_provider` matches `^[a-z][a-z0-9-]*$` (same rule as `domain.ValidTypeToken`); `ticket_id` is non-empty after trimming and has no line break; `ticket_url` parses with `net/url` as an absolute URL whose scheme is `http` or `https` and whose host is non-empty.
- The writer quotes every string (ADR-0071). Pass `document.String(v)`; never pre-quote.
- A bad hand-edited ticket set is visibility only: one warning finding, never an error, never a block (no new blocking gates).
- Never contact a ticket system; no real site or project name in any fixture. Fixtures use `https://tickets.example.com/browse/CLOUD-123`.
- docket's own `.docket.yml` must never carry a `tickets` key.
- Every `tickets.*` key is `scopeRepoOnly`, `dispSupported`. Strings default `""` and must be single-line; `auto.*` are bools defaulting `false`.
- Cross-references in maintained source anchor on a symbol name or quoted clause, never a line number.
- After editing anything under `skills/` or `.docket.example.yml`, run `go generate ./internal/assets/` and commit the regenerated twins in the same commit.
- Run every focused Go test with `-count=1` (the result cache can serve a stale PASS against a mutated tree).
- The ADR named in the spec ("Ticket fields are three flat stored scalars, and `issue:` is retired") is recorded by implement-next's Step 6 through `docket-adr`. No build task writes an ADR.

## Review Focus

1. **A ticket id or URL with Markdown-breaking characters** (`|`, `[`, `]` in the id; a space, `(`, `)`, `|`, `<`, `>` in the URL). The Ticket row must stay one table row with a working link. Test: Task 3, `TestArtifactTicketRowEscapes`.
2. **A ticket field hand-edited into a YAML mapping or list** (`ticket_url: {a: b}`). It must produce the `ticket-link-invalid` warning, never an error-severity `field-malformed` that would make the record invalid. Test: Task 2, `TestDecodeTicketNonScalarIsWarningOnly`.
3. **A record that carries none of the three keys**, which is every record written before this change, archived ones included. It must decode with no finding; linking it inserts the keys; unlinking it is `nothing-to-unlink`. Tests: Task 2 `TestDecodeTicketAbsentKeysNoFinding`, Task 5 `TestLinkTicketPlanInsertsMissingKeys` and `TestLinkTicketPlanUnlinkNothingToUnlink`.
4. **URL edge spellings.** `HTTPS://Host/x` is accepted (`net/url` lowercases the scheme). `javascript:alert(1)`, `/browse/X`, `mailto:a@b`, `https:///x` (no host), and `ftp://h/x` are rejected. Test: Task 1, `TestValidateTicketURL`.
5. **Repeat and whitespace requests.** A `replace: true` request carrying the current link is `already-linked` and writes nothing. An id of only spaces is `invalid-ticket-id`. A request whose fields are `""` counts those fields as not given, so `{provider:"jira", id:"", url:"…"}` is `partial-ticket`. Tests: Task 4 `TestTicketRequestFindings`, Task 5 `TestLinkTicketPlanReplaceSameIsAlreadyLinked`.

**Behavior the tests pin:**
- Pre-engine request checks (invalid-input, no engine call), in this order and short-circuiting:
  1. `validateLifecycleShape("change_id", …)`. If it returns findings, return them alone. This keeps `TestRequiredTagMatchesValidator`'s empty-request join exact.
  2. `Unlink` together with any ticket field or `Replace` → `unlink-with-ticket`.
  3. Not unlinking and no field given → `empty-request`.
  4. Otherwise, when not unlinking, `ticketRequestFindings`.
- `Plan`, on the attempt's snapshot:
  - The change is not found → `not-found`. A request path that differs from `c.Path()`, or a missing source → `path-mismatch`.
  - Link mode:
    - Current `Ticket()` ok and equal to the request (exact string compare of all three) → empty plan, which the engine reports as no-op (`already-linked`), whatever `Replace` says.
    - A different valid link, or `HasTicketFields()` without a valid link → `already-linked-elsewhere` unless `Replace`. With `Replace`, write and report `replaced`.
    - No ticket fields → write and report `linked`.
  - Unlink mode: `HasTicketFields()` → set each of the three keys that exists in the frontmatter to `document.Null()` (never insert an absent key) and report `unlinked`. Otherwise return an empty plan (`nothing-to-unlink`).
