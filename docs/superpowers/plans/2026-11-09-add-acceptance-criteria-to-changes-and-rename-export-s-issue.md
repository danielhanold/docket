# Acceptance Criteria on Changes and Export `ticket` Kind Implementation Plan

> **For agentic workers:** This plan is executed by `docket-build` (task-by-task through the `docket-build-task` contract, one commit per task, one full-suite gate at the end). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional `## Acceptance criteria` change-body section (writable by `change.create`, editable through the owned-section splicer, placed in proposal order when added later) and rename the change-record export kind from `issue` to `ticket`, adding the section to its allowlist.

**Architecture:** Ordered placement is a narrow extension of `render.ApplySectionEdits`: an absent proposal heading that would today be appended at EOF is instead inserted next to its nearest present proposal neighbour, judged against the record after the request's in-place splices and earlier insertions. `"## Acceptance criteria"` joins `render.ChangeOwnedHeadings`, so every owned-section caller (`change.groom`, reconcile, lifecycle/kill/claim) picks it up with no per-operation code. `change.create` gains one optional, blank-normalized, digest-compatible body field. The export rename is a mechanical identifier rename in `internal/export` plus one allowlist entry.

**Tech Stack:** Go (stdlib `testing`), Markdown skill bodies with embedded twins regenerated by `go generate ./internal/assets/`.

**Spec:** `docs/superpowers/specs/2026-11-09-add-acceptance-criteria-to-changes-and-rename-export-s-issue-design.md` (metadata branch). Read it alongside this plan; its "Settled decisions" and "Decisions made at grooming" are binding.

## Global Constraints

- Proposal order, verbatim: `## Why`, `## What changes`, `## Acceptance criteria`, `## Out of scope`, `## Open questions`.
- `## Acceptance criteria` is optional and **never a build gate**: no change to status readiness, the selector, or the board.
- Blank (whitespace-only) `acceptance_criteria` on `change.create` is absent — no section, no error, digests as absent.
- New finding code: `invalid-acceptance_criteria`.
- Export kind value `ticket`; exported change file name `<date>-ticket-<slug>.md`. **No compatibility alias** for `issue`.
- Not renamed: `cleanTitle`'s "another issue" / "other issues" wording (`internal/export/refs.go`); the `"issue"` key in `internal/reposetup/repair.go`; any archived spec text.
- No migration: existing records whose proposal sections are already out of order are not reordered; only a section being added is placed.
- Non-proposal absent sections (Reconcile log, Why deferred, Why killed, Auto-groom blocked, …) still append at EOF exactly as today.
- Docs describe only current behavior: no change numbers or history in skill/convention text.
- Comments anchor on symbol names or quoted clauses, never line numbers (ADR-0054).
- Go test reruns that probe a mutation must defeat the cache: `-count=1`.
- Whole-suite gate: `go run ./cmd/docket development test` (the configured `build.test_command`); read the budget report even when green.

## Review Focus

1. **No blank line before the insertion point** — the predecessor section ends `body\n## Next` (no blank line). Expected: the inserted section is still preceded by exactly one blank line; no existing byte is deleted. Pinned in Task 1 (`TestApplySectionEditsProposalInsertAddsMissingBlankLine`).
2. **Same request removes a predecessor and adds a successor** — request removes `## What changes` and adds `## Acceptance criteria` on a record with Why, What changes, Out of scope. Expected: "present" is judged after the removal, so criteria land right after `## Why` (its nearest present predecessor), before `## Out of scope`. Pinned in Task 1 (`TestApplySectionEditsProposalJudgedAgainstEditedRecord`).
3. **CRLF record, mid-file insertion** — the inserted section uses `\r\n` throughout and the bytes around it are unchanged. Pinned in Task 1 (`TestApplySectionEditsProposalInsertCRLF`).
4. **A proposal heading that appears only inside a fenced code block** does not count as present (the fence-aware scanner already skips it). Expected: placement ignores it. Pinned in Task 1 (`TestApplySectionEditsProposalIgnoresFencedHeading`).
5. **Criteria body with `###` subsections or a closed fence holding `## ` text** is accepted by `change.create` and lands inside the one section. Pinned in Task 3 (`TestChangeCreateAcceptanceCriteria` "subsection and fenced heading" case).
