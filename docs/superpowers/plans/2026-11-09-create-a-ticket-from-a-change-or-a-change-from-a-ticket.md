## Review Focus

1. **The skill reads `status --json` without `--records`.** The `records` array is opt-in; without the flag every change looks unlinked and push would create a duplicate ticket. Test: Task 2's pinned "Known links come from …" sentence ends in `--json --records`, and its Step 6 mutation drops `--records`.
2. **An archived or type-filtered linked change.** It is absent from `changes` but its `records` row must still carry `ticket`. Test: Task 1, `TestStatusRecordsCarryTicket` (archived row; `Types: []string{"feat"}` filter).
3. **A non-change record or an unlinked change in `records`.** ADR and learning rows, and changes with no, partial, or invalid ticket fields, carry no `ticket` key at all (not `null`, not `{}`). Test: Task 1, JSON-level key absence in `TestStatusRecordsCarryTicket`.
4. **Pushing a change whose ticket fields are broken.** The ticket would be created and then could never be recorded. The stop must come before the readiness check. Test: Task 3's sentinel binds `ticket-link-invalid` to "stop here".
5. **A shared repository whose spec has no URL** (`open` returns `target_kind: file`). A local path must never reach the ticket; the spec is attached instead. Test: Task 3's sentinel on "A local path never goes into a ticket".
