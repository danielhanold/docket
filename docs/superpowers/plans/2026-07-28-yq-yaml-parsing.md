The dispatch must carry every element below verbatim in substance — the sub-agent has no other source:

**Title (approximate — the dispatch may sharpen the wording, not the meaning):** docket parses YAML and frontmatter with in-repo shell readers — no external YAML parser.

**Frontmatter:** `change: 18`, `relates_to: [57, 58]`, `supersedes: []`, `reverses: []`, `status: Accepted`, `date: 2026-07-28`.

**Context** — the forces:
- docket's shell scripts read YAML and markdown frontmatter with hand-rolled `sed`/`awk`/`grep`. The readers today are `sync-agents.sh` (repo root, `section_body()` / `field_of()` / `harness_agent_line()`), `scripts/docket-config.sh`, `scripts/lib/docket-frontmatter.sh` (`field_raw` / `field` / `fm_field` / `list_field` / `int_field`), and `scripts/lib/docket-runtime.sh` (the `runtime.bash` declaration reader, changes 0133/0152).
- Adopting `yq` was tracked as an open question from 2026-06-16 (this change's original framing). It was never adopted, and docket then invested in the opposite direction — centralizing the readers and writing ADR-0057 and ADR-0058 *about* them.
- The question is therefore closed by conduct but never written down, which is what this ADR fixes.

**Decision** — what was chosen:
- docket parses YAML and markdown frontmatter with in-repo shell readers and takes **no dependency on `yq` or any external YAML parser**.
- State the boundary honestly: this is **not** a zero-external-dependency claim. Change 0132 established that docket validates a configured GNU Bash 4+ runtime. The rule is narrower and exact — no external *YAML parser*.

**Reasons that actually held** (the three that survived, not a rationalization):
1. **The install pitch is clone-and-run.** A YAML parser is a binary every user and every CI runner would have to acquire before docket works at all.
2. **The two `yq` forks are incompatible binaries** — `mikefarah`'s Go implementation and `kislyuk`'s Python one share a name and not a CLI. Adoption is not "use yq", it is "pin one fork and detect the other", and being wrong is silent.
3. **The parsed surface is a documented block-style subset, not arbitrary YAML.** docket's own config and frontmatter are flat scalars and single-line lists by design; a general parser buys generality the format does not use.

**Consequences** — including the cost, stated plainly:
- The hand readers handle a **subset**. Top-level flow-style mappings (e.g. `agents: {…}`) are **silently ignored rather than parsed** — `section_body()` matches only a bare header, so a flow-style mapping never enters the block. This is accepted, not unnoticed.
- Quoting, spacing, and multi-line scalar forms outside the documented subset are likewise not supported.
- ADR-0057 (a frontmatter read must be anchored when the key may be absent) and ADR-0058 (the two-tier `field()` vs `field_raw()` reader split) decide *how* the in-repo readers behave, and only make sense under this stance. This ADR carries `relates_to: [57, 58]`; **their** `relates_to: []` is NOT to be edited back — both are Accepted and immutable except their `status:` line.
- Re-opening adoption is a **new ADR superseding this one**, never an edit — and it would be all-or-nothing across every reader, never one bilingual script.
- `scripts/lib/docket-runtime.sh` must additionally run under macOS system Bash 3.2, which tightens rather than loosens the stance.

**Explicitly excluded from the ADR:** the pre-refactor helper names `entry_line` and `block_names`; any line-number citation (the `(no yq)` comment in `scripts/docket-config.sh` has already drifted once); and the phrase "zero dependencies".
